# ATLAS Product Principles

## 1. Source First

Every technical claim that could materially affect analyst decisions must be attributable to one or more sources.

## 2. Canonical Concept Before Vendor Syntax

The underlying event, behavior, artifact or technique is canonical. Vendor-specific queries are representations/operationalizations of that concept.

## 3. Exact Before Intelligent

Exact identifiers such as Event ID, Sysmon ID, ATT&CK ID, CVE, provider, record ID and field name resolve deterministically before optional semantic ranking.

## 4. AI Must Be Grounded

AI may summarize, correlate, explain and propose pivots. It must not silently invent facts, mappings, citations or engine syntax and never becomes canonical truth.

## 5. Offline Is a First-Class Mode

Core installed-pack search, record detail, relationships and provenance must work without mandatory Internet access.

## 6. Validation Status Is Explicit

Draft, static validation, engine/fixture/lab validation, production-candidate and production validation states must not be collapsed.

## 7. Applicability Beats Coverage Count

ATLAS says N/A, unsupported, unknown or out-of-scope when appropriate rather than manufacturing a misleading relationship or translation.

## 8. Coverage Requires a Denominator

No "complete" coverage claim is valid without explicit provider/channel/version/scope. A parser or source profile alone does not count as delivered corpus coverage.

## 9. Fast Analyst UX

Keyboard-first navigation, strong search, readable evidence views and minimal navigation depth are preferred over decorative dashboards.

## 10. Version Everything That Can Drift

Sources, schemas, telemetry semantics, applicability, relationships, query syntax and packs retain version/freshness context.

## 11. One Knowledge Truth Across Product Surfaces

Desktop, CLI, Web, iOS Safari PWA, API and future native/cross-platform applications consume shared canonical contracts. No surface may silently become a parallel knowledge implementation.

## 12. Public Trust Before Public Release

The source repository may be publicly inspectable before binary release. Public Preview publication still requires explicit licensing, redistribution, signing, packaging, accessibility, security and governance evidence.

## 13. Fail Closed on Trust

Invalid pack metadata, corrupted targets, rollback violations, incompatible schema or missing trust evidence must fail closed rather than silently degrade to untrusted content.
